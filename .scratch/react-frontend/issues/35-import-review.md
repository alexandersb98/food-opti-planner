# 35: Reviewing an imported recipe

**What to build:** A finished import opens as a new spread in edit mode under review: a banner says where it came from (pasted text or the site's name), how many lines need the owner, and that the end was left out when the text was long. Each imported line shows its original text and what it needs: pick an ingredient (search starting from the line's food, with "+ New ingredient" opening the ingredient form in a sheet with the food as the name and matching the line once saved), give a factor ("1 dl = [100] g", the AI's suggestion to accept or change), pick another unit, or skip; skipped lines are greyed with "Add anyway" or "Add back". Save is blocked with "Match, convert or skip every line to save" until each line is settled; accepted factors are saved as conversions with the recipe (AI-suggested until edited). Leaving an unsaved import asks "Discard this recipe?" with "Keep editing" and "Discard".

## Comments

**Where things are** (`web/src/app/pages/recipe/`): `ImportReview.tsx` (`useImportReview(...)`: the banner, each line's review, the picker and new-ingredient sheets, `needs` and `refuse()`; `LeaveGuard`: the router blocker, the Confirm sheet and a `beforeunload` warning), `reviewEdits.ts` (pure draft changes: `matchLine`, `skipLine`, `acceptFactor`, `forgetFactor`, run through `useRecipeDraft`'s `edit`), `import-review.css` (`review-` prefix, D2's `--review`/`--review-ink`), `ImportReview.test.tsx` (21 app tests).

**Hooked in at the places left.** `NewRecipe` calls `useImportedDraft()` at mount (before the catalogue loads, so a retry keeps it) and passes `imported`; the bar's hint becomes "Reviewing an imported recipe" and the caption counts the imported lines. `SpreadEditor` renders `review.banner` at the marked line above the head, passes `review.line` to `LineEditor` (new optional prop `review`), and renders the sheets and `<LeaveGuard>` only for an import. `LineRow` takes the review's parts: the source text above the line (`grid-column: 1 / -1`), the panel under it, classes `review-line`/`review-needs`/`review-skipped`, a skipped line's amount and unit disabled, and no "doesn't convert" note while the review explains the unit. `withIngredient` in `RecipeSpread.tsx` now also adds an ingredient it doesn't know (the new one). `IngredientPicker` gained an optional `noMatch(search)` so the review says "No ingredient is called “honey” yet. Make it here:" above "+ New ingredient" instead of "Add it on the Ingredients page first".

**Decisions and differences from Vue/D2.**
- Save stays enabled (ticket 27's rule: disabled only while saving). The banner always says "Match, convert or skip every line to save." while lines need the owner; pressing Save then sends nothing, says it again as an alert, and moves the focus to the first line that needs the owner (scrolled to the centre). Vue disabled Save.
- The banner is not a button (Vue's was): it holds a real text button "Show the next line that needs you", cycling through the lines and focusing each one's first action. Its count line is `aria-live="polite"`. A kicker "Imported, not yet saved" over it; with every line ready it fades to a paler wash.
- Line panel after D2's review note: "Needs review." on its own line, then the reason (unmatched: "None of your ingredients is matched to “milk” yet."; factor: D2's "We don’t know what 1 dl of almonds weighs, so it’s left out of the totals."; bad unit: Vue's message), then the actions. Factor row "1 dl = [50] g ✨ Accept" (✨ is `role="img"` named "Suggested by AI, not checked by you"); accepted: "1 dl = 50 g ✨ Change". Enter in the factor box accepts. Accept is disabled for an empty or invalid number, and an invalid one says why (Vue parity).
- Skipped: amount, unit and name greyed, the name struck through; "Skipped" / "Not an ingredient, so left out" with "Add back" / "Add anyway". Every review button is named for its line ("Skip: milk").
- Focus: pick → the line's amount (or its factor box when it needs one); Accept → Change; Change → the box; Skip → Add back; Add back → Pick ingredient or the amount.
- "+ New ingredient" closes the picker and opens `IngredientForm` (`id={null} initialName inSheet`) in a full-screen sheet through a portal, wrapped in a `div` that stops its submit reaching the recipe's form (tested: without it the refused-save alert appears). Saving adds the ingredient to the page, matches the line and asks `POST /api/recipe-imports/factor`.
- Leaving: React Router's `useBlocker` (only for imports, only when the path changes) with the Confirm sheet "Discard this recipe?" / "It was imported and is not saved yet." / Keep editing / Discard (destructive). A save sets a ref so its own navigation is not stopped. A reload or closed tab gets the browser's `beforeunload` warning (Vue had it too).
